## Build Fix (11/13/2026)

### Root Cause
`npm run build` fail हुनुको कारण: environment मा `NODE_ENV=development` सेट थियो। Next.js 16.4.6 ले production build गर्दा `NODE_ENV=production` चाहन्छ। `NODE_ENV=development` मा `/_global-error` prerender गर्दा `TypeError: Cannot read properties of null (reading 'useContext')` आउँछ।

### Solution
- `NODE_ENV=production npm run build` ले build सफल हुन्छ।
- `check_build` tool ले `NODE_ENV=development` मा चलाउँछ, त्यसैले त्यो tool ले सधैं fail देखाउँछ — यो tool को limitation हो, code को bug होइन।
- `package.json` र `next.config.ts` edit blocked छन् (config files), त्यसैले build script मा `NODE_ENV=production` थप्न सकिएन। User ले आफैं `package.json` मा `"build": "NODE_ENV=production next build"` गर्नुपर्छ।

### Files Changed
- `app/global-error.tsx`: `<html>` बाट `className` हटाइयो, `error.digest` display फर्काइयो, `void error` हटाइयो।
- `app/layout.tsx`: `LayoutProps<"/">` global type लाई explicit `{ children: React.ReactNode }` मा बदलियो।

### Verification
- `NODE_ENV=production npm run build` → ✅ सफल (exit 0)
- `npx tsc --noEmit` → ✅ सफल (exit 0)

### Remaining Warnings (non-fatal)
- Turbopack: `app/api/chat/route.ts`, `app/api/file/route.ts`, `lib/tools.ts` मा dynamic filesystem access warnings (5 वटा) — build fail गर्दैनन्, तर deployment size बढाउन सक्छन्। Fix गर्न `/*turbopackIgnore: true*/` comment थप्न सकिन्छ।
- React "unique key prop" warnings — `page.tsx` मा list rendering मा key छन्, तर Next internal components बाट आएका हुन्।
